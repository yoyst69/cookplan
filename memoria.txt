------------------------------------------------------------------------
1. Objetivo del proyecto
------------------------------------------------------------------------
Aplicacion CookPlan para el hogar: planificacion semanal de comidas
evitando repeticiones, generacion de la lista de la compra a partir del
menu, y reparto de tareas domesticas del fin de semana entre los
miembros de la casa (Fiti, Mar y Jose).

------------------------------------------------------------------------
2. Requisitos funcionales
------------------------------------------------------------------------
2.1. Usuarios
- Registro con confirmacion por correo (o enlace por consola si no hay
  SMTP configurado).
- Roles: administrador (Fiti) y usuarios normales (Mar, Jose). El admin
  crea usuarios, cambia permisos/activo y restablece contrasenas.
- Usuarios iniciales (seed):
    Fiti  admin  admin@cookplan.local / Fiti6969
    Mar          mmarruizg70@gmail.com / 5668
    Jose         jose@cookplan.local / 5668

2.2. Recetas
- Catalogo con foto (multipart -> WebP con sharp), tiempo, personas,
  momento (Desayuno/Comida/Cena), pasos e ingredientes.
- Importacion inicial de 40 recetas de Mar desde scripts/recetasDataA.ts
  + recetasDataB.ts (fuente: Recetas.Mar.docx). Importador idempotente:
  scripts/import-recetas.ts.

2.3. Plan semanal
- Tabla 7 dias x 2 slots (comida y cena). El generador rellena solo los
  huecos vacios.
- Anti-repeticion: una receta no se repite si se uso en los ultimos
  dias_sin_repetir dias (por usuario, 21 por defecto) ni en la misma
  semana. GET /plan/sugerencias devuelve sugerencias con diasSinUsar.

2.4. Lista de la compra
- Origen MENU (generada desde el plan agrupando ingredientes) y MANUAL
  (productos a mano). Check/tachado, cantidad opcional y equivalencias
  (ej. 3 dientes = 1 cabeza de ajo).

------------------------------------------------------------------------
3. Tareas domesticas (nueva zona)
------------------------------------------------------------------------
- Reparto automatico del fin de semana (sabado + domingo) entre las 3
  personas del hogar.
- Catalogo inicial de 15 tareas con peso de esfuerzo (1-3): pasar la
  aspiradora, limpiar el bano, sacar la basura, cocinar el fin de
  semana, etc.
- Algoritmo: greedy equilibrado por peso con rotacion semanal; cada
  persona reparte sus tareas entre sabado/domingo balanceando esfuerzo.
  Reemplaza solo asignaciones generadas previas; las manuales
  (generado=false) se respetan.
- Cualquier usuario autenticado puede generar el reparto y anadir
  tareas al catalogo; el admin gestiona usuarios.
- Config tareas_personas (ids de Fiti,Mar,Jose). Las personas del
  reparto se calculan por prefijo de nombre (los posibles prefijos se
  guardan en la config por si cambian los nombres).

------------------------------------------------------------------------
3.1. Notificaciones
- Al generar el reparto o asignar una tarea a mano, cada persona con
  tareas pendientes recibe una notificacion en la app con el detalle
  ("Fiti te ha asignado N tareas..." / "Mar te ha asignado la tarea...").
- Al marcar como finalizada una tarea, se notifica a quien la asigno
  ("Jose ha finalizado la tarea Limpiar el bano").
- Modelo Notificacion (titulo/mensaje/tipo/leida) + campo
  asignadaPorId en AsignacionTarea. Rutas: GET /api/notificaciones,
  GET /no-leidas, PATCH /:id, POST /leer-todas. Web: campana con
  badge de no leidas (polling 30 s) y panel con historial.
- Correccion: el generador ya no asigna una tarea a una persona que la
  tiene asignada a mano (constraint unico usuarioId,tareaId,semana).

4. Entorno y arquitectura
------------------------------------------------------------------------
- Windows (win32), PowerShell 5.1. Stack replicado de quiniela_app_new /
  GM-PrintFlow: monorepo app/ con packages/api (Express + TypeScript +
  Prisma) y packages/web (Vite + React + TypeScript + Tailwind 4).
- Base de datos: PostgreSQL 15 en Docker, puerto 5435
  (user/db/pass = cookplan), contenedor cookplan-db.
- Puertos: API 3004, dev server web 5176 (proxy /api y /uploads -> 3004).
- Tema: dark por defecto con modo claro; clases utilitarias card, btn,
  input, badge; acento naranja (#f97316).

6. API REST (packages/api)
------------------------------------------------------------------------
  /api/health
  /api/auth          login, registro, confirmar, recuperar, reset,
                     perfil + logo
  /api/recetas       CRUD + foto
  /api/plan          get, guardar, generar, sugerencias
  /api/lista-compra  get, crear, patchear, borrar, generar desde menu
  /api/tareas        reparto + catalogo + asignaciones
  /api/usuarios      gestion de usuarios (admin)
- JWT Bearer; middleware de auth con req.usuario; fotos con multer 2.x
  + sharp (WebP).
- Email: si existe SMTP_HOST envia correos reales; si no, el enlace se
  muestra por consola.

7. Frontend web (packages/web)
------------------------------------------------------------------------
- Paginas: Login, Register, Confirmar, Recuperar, Reset, NotFound,
  Recetas (grid + CRUD + ver), Plan (tabla semanal + picker con
  sugerencias), Lista, Tareas domesticas, Perfil, Usuarios (admin).
- Contextos: Auth (cp_token/cp_usuario, guardas Privado/Admin) y Tema
  (cp-theme). Axios centralizado con interceptor de token y manejo 401.
- Build de produccion en verde (tsc && vite build); proxy del dev server
  probado de extremo a extremo (login via 5176).
- Capacitor 8: plataforma Android anadida (appId com.cookplan.app,
  webDir dist). Para la app real compilar con VITE_API_URL apuntando a
  la API desplegada.
